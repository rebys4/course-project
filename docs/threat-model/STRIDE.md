# STRIDE: Поток/Элемент → Угроза → Контроль

**Цель:** связать угрозы с контролями и NFR. Категории: **S**poofing, **T**ampering, **R**epudiation, **I**nformation disclosure, **D**enial of service, **E**levation of privilege.

| Поток/Элемент | Категория | Угроза | Контроль (ссылка на NFR / практику) |
|---|---|---|---|
| **F1: Client → API (HTTPS)** | T/I | Подмена/прослушка трафика | **NFR-08**: HTTPS + HSTS; отказ от HTTP, редирект на HTTPS |
| F1 | S | Спуфинг клиента | **NFR-04**: JWT-проверка на защищённых эндпоинтах; отклонение без токена |
| F1 | D | Нагруженные вызовы | **NFR-01**: p95 ≤ 200мс; лимит RPS на уровне gateway (план) |
| **Auth Service (F2/F3)** | S | Спуфинг учётных данных | **NFR-03**: Argon2id (память ≥ 64MB, итерации ≥ 3) для паролей |
| Auth (F3) | T/I | Подделка/утечка токенов | **NFR-04**: TTL ≤ 1h; подпись серверным ключом; хранение ключей в секретах (**NFR-07**) |
| Auth (F2) | D | Брутфорс/перебор пароля | **NFR-05**: rate limit 5/мин (после 5 попыток — 429) |
| **F4: API → Topics Service** | E | Обход авторизации | Проверка JWT + **owner-only** в коде эндпоинтов (уже реализовано); **NFR-04** (валидность токена) |
| F4/F4a: CRUD/Store | T/I | Модификация чужих данных | **owner-only** доступ (код), валидация ID и принадлежности; **NFR-06** аудит логов |
| F4/F4a | R | Отрицание действий | **NFR-06**: логи с `trace_id` и user_id; событийные логи для изменений |
| **F5/F5a: Monitoring/Logging** | I | Утечка чувствительных данных в логах | Политика маскирования PII; **NFR-06**: контроль состава логов в CI |
| F5 | D | Необнаруженная деградация | **NFR-02**: uptime ≥ 99.5%; алерты по SLO |
| **F6/F6a: CI/CD & Secrets** | T/I/I | Подмена артефактов/секретов, утечка | **NFR-07**: секреты только в GitHub Secrets, ротация ≤ 90д; ограничение прав CI |
| API Gateway | D | DoS | **NFR-01**: цели по задержкам; rate limit на публичные пути; health-checks (**NFR-02**) |
| Topics Service | E | Повышение привилегий | Минимальные роли; отказ от скрытых админ-эндпоинтов; JWT скоп у токена (**NFR-04**) |

## Примечания
- **Owner-only** контроль реализован в коде: проверка `owner_id` для `/topics/{id}` (403 при чужом доступе).
- Все сетевые каналы, особенно **F1**, должны строго принуждать HTTPS/HSTS (**NFR-08**).
- Секреты, ключи подписи JWT — в секрет-хранилище, с ротацией (**NFR-07**).
